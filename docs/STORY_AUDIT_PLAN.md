# 故事内容质量检测计划

本文档用于规划如何在不通读全部正文的前提下，系统检测 `stories/` 下 440 集故事中可能存在的问题，包括格式问题、语句问题、情节脱节、设定冲突、角色失真和儿童可读性问题。

## 目标

1. 建立一套可重复运行的检测流程，避免每次依赖人工从头阅读。
2. 将问题分成“可脚本检测”和“需要人工/LLM 判断”两类。
3. 优先发现高风险问题：设定冲突、前后衔接断裂、角色行为不一致、价值观偏离。
4. 让后续润色、修订、续写都能遵守 `CLAUDE.md` 和 `docs/STYLE_GUIDE.md`。

## 基准文档

检测故事内容时，以以下文档为主要依据：

- `CLAUDE.md`：项目级工作规则、冲突处理优先级、上下文读取要求。
- `docs/STYLE_GUIDE.md`：格式、叙事、语言、价值观、互动时刻规则。
- `docs/lore/人物志.md`：角色关系、能力边界、性格和成长弧光。
- `docs/lore/世界观大纲.md`：世界观、历史、地理、文明和核心规则。
- `docs/lore/故事设定逻辑.md`：发明、科学、奇幻机制和叙事逻辑。
- `docs/主角成长路线.md`：小金、小彩逐季成长阶段。

## 问题分类

### P0：必须优先处理

- 故事正文与既有重大设定冲突。
- 角色关系、死亡/转化/重生状态前后矛盾。
- 相邻集之间关键事件无法衔接。
- 主角能力突然变成无铺垫、无代价的万能解法。
- 价值观明显偏离项目基调，例如以消灭、羞辱、强制控制作为最终正向答案。

### P1：应当修复

- 前情回顾使用“上一集”“本集”“下一集”“这一季”等文档元信息。
- 互动时刻格式或四个固定维度不符合 `STYLE_GUIDE.md`。
- 中文正文混用英文标点、省略号、破折号或引号。
- 角色语气明显不符合人物志或当前成长阶段。
- 本集结尾悬念和下一集开头没有自然承接。
- 儿童读者难以理解的长句、抽象议论或成人化说教过多。

### P2：建议优化

- 段落过长，单段承载过多动作或设定解释。
- 冒险段落缺少动作推进，变成静态说明。
- 温情段落缺少具体动作和感官细节。
- 重复使用同一种结构，例如“开会、立规则、出悬念”过密。
- 微观尺度感不足，场景像普通人类视角。

## 检测层级

### 第一层：全量脚本扫描

目标是低成本扫描全部故事文件，快速发现硬性问题。

现有脚本：

```bash
python3 scripts/validate_story_format.py
```

当前脚本主要检查：

- 标题是否与文件名一致。
- 前情回顾位置和长度。
- 正文字数范围。
- 正文前后分隔线。
- 互动时刻基本结构。

建议新增脚本或扩展现有脚本，检查：

- 文档元信息：`上一集`、`这一集`、`本集`、`下一集`、`上一季`、`这一季`、`下一季`。
- 英文标点混用：`...`、`......`、`!`、`?`、英文引号、英文冒号。
- 互动时刻四个小标题是否严格为：`自我调节`、`换位思考`、`智慧与宽容`、`悬念预测`。
- 互动问题是否全部以中文问号 `？` 结尾。
- 疑似多余 Markdown 标记，例如前情回顾末尾异常出现 `**`。
- 疑似暴力或不适合儿童表达：`杀死`、`干掉`、`尸体`、`血腥` 等。
- 长句：单句超过建议阈值时输出位置，供后续人工判断。

建议新增命令：

```bash
python3 scripts/audit_story_text.py
```

输出格式建议：

```text
文件路径:行号 [严重程度] 问题类型：说明
```

### 第二层：相邻集连续性抽检

目标是检测情节脱节。无需整集通读，使用滑动窗口抽检。

每次读取：

- 第 N-1 集结尾 500-800 字。
- 第 N 集前情回顾。
- 第 N 集开头 800-1200 字。
- 第 N 集结尾 500-800 字。

固定检查问题：

1. 第 N 集前情回顾是否准确承接第 N-1 集结尾？
2. 第 N 集开头是否回应上一段经历留下的悬念？
3. 本集核心冲突是否有清楚起因、过程和结果？
4. 解决方案是否有铺垫、代价和限制？
5. 结尾悬念是否能自然引向下一集？
6. 是否出现角色能力、人物关系、地点状态或规则前后矛盾？

建议优先抽检范围：

- 每季第 01-03 集：季初承接和新主线建立。
- 每季第 18-22 集：中段转折。
- 每季第 38-40 集：季终收束和下一季引子。
- 设定变化密集集数，例如重生、转化、能力觉醒、迁居、协约签署。

### 第三层：设定与角色一致性审计

目标是发现脚本无法判断的软问题。

审计时每次只选择一个明确问题，不做大范围泛读。例如：

- “小彩在第十季是否符合共同决策参与者的定位？”
- “黑焰在第三季后是否仍出现单薄反派式语气？”
- “小金是否在第十一季真正退到顾问位置，还是仍然替后来者解决一切？”
- “记忆孢子、小玉金色植物、全球植物网络的设定是否前后一致？”

审计输出格式：

```text
文件：
位置：
问题类型：
严重程度：
依据文档：
问题说明：
建议处理方向：
```

要求：

- 不凭印象判断，必须引用当前故事片段和基准文档。
- 不直接大改正文，只输出问题清单和修改方向。
- 如果发现冲突涉及大量正文，先记录为待确认问题，不立即批量改。

## 故事索引建设

长期建议建立 `docs/story_index.json`，为每集维护结构化摘要。

每集建议字段：

```json
{
  "file": "stories/第10季_地球回响篇/第20集_四法则落到今天.md",
  "season": 10,
  "episode": 20,
  "title": "四法则落到今天",
  "main_events": [],
  "characters": [],
  "locations": [],
  "new_rules": [],
  "resolved_threads": [],
  "open_threads": [],
  "character_growth": [],
  "continuity_notes": []
}
```

索引用途：

- 快速查找某角色在哪些集出现。
- 快速定位某设定首次出现和后续变化。
- 检查伏笔是否回收。
- 检查某季主线是否完整。
- 为后续续写提供上下文，而不是每次读取大量正文。

## 推荐实施顺序

### 阶段一：补强硬性检测

1. 扩展 `scripts/validate_story_format.py` 或新增 `scripts/audit_story_text.py`。
2. 全量扫描 `stories/`。
3. 输出 P1/P2 问题清单。
4. 先不自动改正文，只生成报告。

### 阶段二：修复明确格式问题

1. 处理文档元信息入文，例如把“上一集”改成“上一段经历”“那次事件之后”等世界内表达。
2. 修复英文标点、省略号、破折号、引号问题。
3. 修复互动时刻标题不固定、问题不以中文问号结尾等问题。
4. 每次修复后运行格式校验。

### 阶段三：连续性抽检

1. 每季抽检 8-10 个相邻窗口。
2. 优先覆盖季初、季中、季末和重大设定变化集。
3. 生成 `docs/audit_reports/` 下的审计报告。
4. 将 P0/P1 问题单独列出，等待确认后再修改。

### 阶段四：建设故事索引

1. 先为每季第 01、20、40 集建立索引样例。
2. 确认字段足够后，再逐季补全。
3. 后续新增或修改故事时，同步更新索引。

## 验收标准

阶段一完成时：

- 能一条命令扫描全部故事。
- 能输出文档元信息、标点、互动标题、长句和敏感表达问题。
- 原有 `validate_story_format.py` 继续通过。

阶段二完成时：

- 全量故事不再出现禁止的文档元信息。
- 互动时刻四个维度全部符合固定格式。
- 明显中英文标点混用问题基本清除。

阶段三完成时：

- 每季至少有一份连续性抽检报告。
- 每个发现的问题都有文件、位置、严重程度和处理建议。
- P0 问题不直接静默修改，先确认处理策略。

阶段四完成时：

- 至少完成一季完整故事索引。
- 后续可以通过索引查角色、设定、伏笔和开放线索。

## 注意事项

- 不要因为扫描发现大量问题就批量机械改写故事正文。
- 涉及设定、角色成长和剧情方向的问题，应先形成报告，再决定是否修改。
- 润色必须保护原剧情功能，不随意删除关键情节。
- 所有新增脚本应默认跳过 `_backup` 目录，保持与现有校验脚本一致。
- 输出报告应使用简体中文，路径和命令保持原样。
